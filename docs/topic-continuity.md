# 主题式对话的持续规划与换题

2026-10-15。适用于当前独立 Web POC；学习者数据仍经本地 Mock HSKai 授权端口读取，语音仍为豆包 `next_turn_advisory`。

## 当前行为

主题范围、教学目标、逐轮动作分别管理。初始化选择一个合法目标，之后以选定主题为范围，以表达任务为主线，承接学生实际内容；不要求每轮练习同一句话。暂停练习或完成一次表达尝试，都不自动取消主题。其他兴趣、提示中的纠错例句、教师已经说过的跑题内容，也不授权 Kai 主动换主题。

| 情况 | 状态与处理 |
| --- | --- |
| “我想聊跑步”，当前为运动主题 | 不再仅凭“我想聊”立即暂停目标；Planner 判断主题内选题，继续承接 |
| “跑步时听音乐让我更容易坚持” | 允许相关联想；后续追问仍联系运动体验，不以“音乐”这个词判换题 |
| 只提到一个无关内容，没有换题意愿 | 简短承接后自然连接当前主题，不展开独立新话题，也不指责学生 |
| 明确不想练习 | 暂停目标，保留主题，继续交流；不自动恢复练习 |
| 明确要求换整个主题 | 暂停旧目标，记录 `change_requested`；页面显示当前选定主题与待切换请求 |
| 澄清不换主题、继续原主题 | 清除待切换请求；已暂停的练习不自动恢复。明确选择合法目标或恢复练习才重新激活 |
| 当前主题资源复核失败 | `unavailable`，停止旧目标教学，语音不再携带该包 brief；页面提示重新选择 |

本会话没有自动加载另一个 Topic Pack。学生可以点击“结束并重新选择主题”，通过现有结束流程收尾，再选新主题或自由聊天；新主题仍须独立准备、验证并建立新会话。页面不会把“已提出切换”显示成“已经切换成功”，也不会沿用运动目标教音乐。

## 状态与调用链路

1. Initializer 按固定资源创建 `topic_scope`：版本、主题 ID／名称／brief、资源版本与 hash、状态、当前请求和最近关系判断。主题状态参与会话计划 hash，与 goal_status 分开。
2. 即时控制仅把清楚的整主题更换表达作为请求；动态主题中的一般“我想聊……”交给语义规划。引语和已识别的转述不操作换题控制。这里识别的是控制表达，不使用运动／音乐等主题词表。
3. 逐轮快照同时携带 `topic_scope`、现有目标／知识点／表达任务、实际前文和三类资料。FullContract 与 Draft adapter 在原有 `planTurn` 调用中输出 `topic_decision`，没有新增同步分类调用；仍共用最多两秒的请求、修复、校验与提交期限。
4. 主题提案使用 `turn-plan-v2`，含 `{topic_id,relation,request_quote,requested_focus,refs}`。关系包括 within_topic、related_context、off_topic、change_requested、uncertain；unassessed 表示尚未判断。非主题入口保持原逐轮字段。
5. 校验固定 topic_id 和当前输入引用；换题请求的 quote 必须来自当前未被引号屏蔽的学生输入，目的话题标签须在 quote 中出现。识别出的转述、伪造引用和别的主题 ID 被拒绝。换题提案不能继续旧目标教学、提高教学负担或替换／恢复旧目标。
6. 接受结果后更新主题状态；只有通过既有时效／版本／取消检查的当前提案才能提交。规则回退保留主题约束，未评估关系不被当成“允许任意换题”。偏好刷新更新资料和支持策略，保留主题的 content_focus。
7. Context Compiler 在初始和后续语音上下文中持续附上主题范围，教学暂停时也保留。后续动作仍须服从主题范围，不能因为任务文本跑题就解除主题。Gateway 复用已有 `teaching.state` 与上下文更新／ACK 消息；Web 根据服务端主题状态展示，不自己判断学生意图。

请求 quote 与当前输入引用只在会话内存及既有显式开启的合成评审快照中使用。Web 只收到主题名称、状态和可选目的话题标签；不增加原始音频、逐字稿保存或学习者能力写回。

## 校验能力与实际限制

来源与状态可由代码核对；“这句话是否想换主题”“回复是否自然且相关”仍是语义判断。引用真实学生片段，只证明来源，不能独立证明模型理解正确。字段校验不等于语义认证：模型若把跑题任务错误标成主题内，仍需语义评测发现，不能宣称所有跑题任务都已被确定性拦截。

主题指令从初始语音配置就存在，可以持续约束豆包生成；外部逐轮结果依旧在安全回复边界更新后续输入。没有新增或声称验证当轮生成门控，也没有把已经播放的语音当成可撤回内容。真实模型完成率、关系判断正确率和多轮语音主题遵循，需分别实测。

评审快照新增主题上下文后，合成 review bundle 升级为 v3；旧 v2 仍按原字段与 hash 验证读取，不为历史 artifact 补写主题状态。评审输入保留原始 topic_scope，并验证它与同一会话计划相符。
