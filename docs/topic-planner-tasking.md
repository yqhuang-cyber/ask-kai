## 1. 三层职责与生成链路

| 层次 | 职责 | 生成／权威边界 |
| --- | --- | --- |
| 通用 Planner | 从三类学习资料、当前意愿、入口和可用资源判断需要，选目标／无目标、支架与观察方向 | 模型提出计划，宿主校验并绑定身份／版本；不写能力事实 |
| 交流能力资源 | 稳定 skill、先修、行为范围、支架、观察 feature 和来源 | 从已有课程／HSK 索引与共用能力定义整理；可由模型辅助提案，发布版本受统一校验；不按主题重写 |
| LLM TopicPack | 主题范围、子话题、情境、skill 关联、候选表达机会、示例和可选卡片 | LLM 生成候选；经过准入的版本供 Planner 使用；不伪装成 HSKai 官方课程 |

管理链路：管理员定义主题 → 独立主题服务发起有界生成 → 结构与内容准入 → 发布固定 TopicPack 版本。学习链路：选择已发布主题 → 读取版本与学习者快照 → 初始化 Planner → 已接受目标实例与支持策略 → 页面／语音 → 实际输入与逐轮调整。在线链路及缓存 miss 均不触发生成。

生成器决定主题里可以怎样交流；Planner 决定当前学生现在适合怎样交流。TopicPack 不含固定学生答案、姓名到目标映射或未来对话脚本。一个能力可以用于多个主题，一个主题也可有多个能力；关联需有语义依据，不机械做全部组合。

## 2. TopicPack 的拟议契约

### 2.1 输入与输出

输入为 topic brief、语言／内容范围、允许 skill 与相关课程来源、生成 policy 和大小限制。默认生成可复用基础包，不发送完整 learner 画像、原始历史或真实逐字稿；学习者个性化主要由 GoalInstance 和 delivery_profile 完成。需要范围信息时仅使用最小能力范围，缓存必须包含该范围。

候选输出包含主题说明、最多 4 个子话题、最多 8 个 skill 关联及其表达机会／推荐支架、可选示例／词卡和 source refs；总大小拟限 24 KiB。数值是待实现的工程上限，不是已测性能。不存在匹配 skill 时可空关联，不临时创造正式 KP 或先修。

来源区分 existing_course、llm_generated 和 host_policy。generator 的 provider／model／prompt、能力资源版本、准入 policy／review 版本、内容 hash、生成时间由宿主记录。不得把生成文本的 source 改成 mock_hskai，也不得让模型填写 authorized、review_passed 或学习者 mastered。

### 2.2 准入与质量

采用 draft → validating → validated 或 validated_restricted；失败为 rejected／failed，旧版本为 stale／revoked。准入后还需按管理服务 policy 发布为 published，才能供学习端读取；模型不能自己发布。没有通过所需检查的字段不进入页面和教学指令。

- 确定性检查：schema／大小、允许 skill／引用、无权威字段注入、主题范围、无固定答案、无身份数据泄漏、版本／请求归属。
- 内容检查：主题与 skill 的关联、语言／示例正确性、问题是否自然、任务负担与内容边界。需自动审阅与开发阶段抽样校准，不能用 JSON 合法冒充语义正确。
- 自动审阅结果与来源留证；同一个模型自评只能算辅助审阅，不能标为独立校准。review adapter 未配置或某项不可评时，保留 unknown。
- validated_restricted 只使用已有可信资源和 policy 能支持的能力关联／交流方向；未经核验的示例、翻译、拼音和卡片不发布。无法满足关联或内容要求则拒绝／管理端重试。未发布的包不能作为“无目标交流”的借口进入在线路径。

无需逐包人工批准。共用准入规则和评测需先校准，生成包按该规则自动处理；新能力或高风险范围另行评审。生成材料获准用于教学不等于学习者已经练过或掌握。

### 2.3 提前发布、存储、缓存与失效

TopicPack 在独立主题管理服务提前生成，按 topic_id 绑定不可变版本。最小管理页面提供主题定义、生成任务状态、版本预览、发布／停用／回滚；支持授权的自动发布 policy，不要求用户逐包人工编写或审批。学习端只展示可用的已发布主题。

生成任务有独立可配置的 deadline／费用／重试限制，原 15 秒仅作为管理端试验起点；记录生成、至多一次修复和内容检查的请求分母，不计作学习者开始等待。初始化暂保留 10 秒预算，逐轮改为最多 2 秒；所有角色可复用文本模型适配能力，不要求购买三个服务。

管理服务持久保存主题定义、准入版本和发布索引；POC 可用独立本机目录及原子更新，不依赖生产数据库。gateway 缓存 key 为 topic_id＋已发布 version／hash＋范围／policy，只加速读取；缓存 miss 从主题服务取已发布包，绝不补生成。发布新版本不覆盖活动会话，收到撤销时失效准备并暂停受影响教学。

管理写入与运行读取权限分开，共享主题存储不包含个人画像；个体 GoalInstance 留在原会话／授权边界。主题服务重启后已发布版本仍可读取，未完成生成标为中断／失败，不盲目重发未知调用。生成存储／私有评测留在 ignored .local，Git 只提交源码、作者合成 fixture 和允许的元数据，不提交 raw provider traces 或真人材料。

未发布、过期、撤销、读取失败均返回明确不可用／准备失败，不能显示已生成成功或回到固定运动课。生成失败和重试由管理端处理；学习端不等待后台生成。已发布包没有适合目标时可以无目标交流，资源不可用与无合适学习目标分开。新请求、取消、撤权隔离迟到结果。

### 2.4 逐轮规划最多 2 秒

从宿主接受有效 user.final／更正版本开始，2000ms 总 deadline 覆盖排队、上下文准备、LLM 请求／body、可选修复、校验、降级和提交；不是“模型请求 2 秒再额外修复”。预留提交时间，剩余不足不修复，不同步调用主题生成器或 Judge；会中复用已绑定资源。

超时执行有来源的保守回应并标记 rule／timeout，deadline 后的 LLM 不能提交。控制动作不等模型；新输入／更正／撤权取消旧工作。2 秒默认与配置上限、输入接受时间锚定、共享修复／校验截止、过期拒绝和耗时记录已实施。TP-07 的通用目标承接仍待实施；真实 LLM 完成率、语义质量及首音另测，单靠 timeout 或全部降级不能验收通过。

## 4. 三批交付节点

### 节点 A：TP-00～04，通用资源和生成基础

### 节点 C：TP-09～11，多主题扩展与分层验收

可演示：另一主题经同一管理服务提前发布，核心无新增 topic 分支；相同学习者跨主题、同能力跨主题与同主题不同需要有对照。真实语义、读取／初始化、2 秒规划完成率和设备结果分别留证，模型失败不被规则成功覆盖。

每个节点同步：交付范围、实际通过的检查、仍未验证的质量、下一步。运行／契约变更运行 npm run verify 和 npm run replay；受影响 UI 增加合成设备检查，真实模型／真实浏览器音频分别记录。

## 6. 评测中的生成与规划隔离

| 对照 | 固定什么 | 检验什么 |
| --- | --- | --- |
| 生成器 | topic brief、能力／来源范围、policy／模型版本 | 情境与能力关联、例子正确性、可用字段、故障／取消 |
| Planner 个性化 | **同一个已准入 pack hash**，只改变学习者需要／兴趣／记录 | 选择与支持是否依据需要，避免生成随机性混入比较 |
| 跨主题 | 学习者快照、能力依据与规划预算 | 任务在新情境中是否仍合适，不只比较目标字符串 |
| 整条链路 | 记录生成包、真实输入、接受计划、执行来源 | 页面／实际语音遵循、等待与错误恢复 |

生成器 rubric／oracle 独立于初始化 28 案。生成语义 holdout、Planner needs holdout 和真实执行样本分别冻结；生成模型自己的评分不充当独立质量证据。无目标有依据可以通过，资料有明确需要但全部回 null 仍需复核。

候选状态、准入字段、引用与取消使用确定性负例；主题关联、语言示例、自然度与支架采用人工校准后的审阅。报告完整分母，不把 generated 当 ready、ready 当 teaching success、teacher output 当 student mastery。
