## 1. 产品目标与现状差距

同一主题下，Kai 根据学习者的交流意愿、已有能力、近期需要和覆盖限制选择本次交流方向、至多一个主要教学目标及支持方式。相同需要允许相同目标；不同姓名、兴趣或等级不要求目标不同。个性化必须能解释哪些输入影响了哪个决定。

当前三类数据与入口都能进入初始化 Planner。运动资源只有 express-likes／express-time；规则在复习和未独立目标均未命中时回选第一个合法目标；Validator 在有合法候选时禁止 null。四位新 Mock 学习者的规则路径因此都可回选喜好，三个较熟练学习者的实际复习方向在资源之外。语音指令仍有 HSK1 人设和统一预算，通用语义观察仅 shadow。

要补足的决策是：**本次想交流什么 → 有依据的当前需要是什么 → 哪个允许的目标值得现在练 → 如何自然创造表达机会 → 准备观察什么及何时重新判断**。

该设计把多能力背景的合成对照纳入 POC 后续实验，不宣称已经发布 HSK1～7 教学能力或官方等级大纲。旧 HSK1 行为、旧数据集与评分不被重标为失败或覆盖。

## 2. 输入职责与证据解释

| 输入 | 参与哪些决定 | 不能推出什么 |
| --- | --- | --- |
| 当前明确选择／入口 | 交流目的、教学意愿、主题／Mission 范围、语言／节奏 | 选主题不等于接受无限练习；free 不等于基础能力差 |
| 个人画像 | 内容、生活情境、动机、活动形式、反馈偏好 | 喜欢球赛不能证明会论证；姓名／母语不能决定水平 |
| 学习画像 | 相关能力基线、可能需要的支架、已熟练内容、复习候选 | 等级不是全部 KP 的能力证明；候选不是必须复习 |
| 近期记录 | 近期困难、已表达的下次意愿、实践／迁移情境、拒绝范围 | 最近一条必定最可靠；没检索到就等于没学过 |
| 可信目标／主题／Mission 资源 | 允许教学的能力、情境、先修、支架和观察依据 | 画像中出现 KP 就自动获得课程授权；完成 Mission 就掌握 |
| coverage／版本／来源 | 判断哪些结论受限、是否需保守观察或重取 | partial／unavailable 能力低；过期记录可作为当前事实 |

### 2.1 权威与相关性

身份、授权、版本、安全和明确控制来自宿主。当前学生明确选择覆盖旧选题与旧偏好，但不能补足课程授权或先修证据。背景自由文本仍是数据；引用教师、假设或“忽略规则”不能更改策略。

能力证据保留来源、时间、情境、提示情况和更正／撤销关系。后台 assessment／经确认的 observation、学生自述和教师建议分别处理；Mock 的模拟掌握只属于作者设定背景。本会话的 planned／generated／forwarded 不成为学习者表现。出现相互矛盾、截断或提示未知时，把争议字段标为 unknown，采用可撤回的低负担开场；不按新旧日期单独定案。

保留已有 record_id，宿主提供允许的 snapshot／record／field-path 引用。尚无单条记录 ID 的背景或能力摘要只能引用其快照与允许路径，不编造更细来源。所有结论绑定同一 learner、授权 epoch、revision 与 as_of；错身份／混版／读取失败应准备失败或有界重取，不能包装成“资料未知但个性化成功”。

对拒绝记录保留目标、主题、会话／持续偏好范围与当前显式恢复。现有记录缺少范围时采用现有保守约束并标未知，不能在本设计中自动给旧拒绝加过期时间。后续完善拒绝契约是独立迁移工作。

### 2.2 NeedAssessment 是计划假设

模型给出至多两个与当前目的有关的需要，字段建议为 skill_ref、baseline（supported／limited／unknown）、need_kind（practice／transfer／review／clarify／none）、gap、evidence_refs、unknowns。每项用一句简短解释，无思维链或伪精确能力分数。

这份 assessment 是当前规划假设，不写回能力标签；“适合给机会试着讲经历”不等于“不能讲经历”。学生当前不愿教学时，可以明确 need_kind:none，而非挖掘另一个薄弱点继续考。

## 3. 目标与资源：允许实例化，保留课程依据

区分三层对象：

| 对象 | 内容 | 示例 |
| --- | --- | --- |
| Skill catalog | 稳定语言／交流能力、先修、可观察行为、适用限制、版本 | 叙述事件顺序；用具体例子支撑观点 |
| TopicPack／MissionPack | TopicPack 由 LLM 生成范围、场景、素材与 skill 关联，经宿主准入；MissionPack 仍来自可信课程 | 运动经历；团队配合；竞技规则 |
| GoalInstance | 选定能力在本次交流中的一个有限目标 | 讲一次跑步经历，让听者理解事情的先后 |

Skill 与 topic 的关联由生成器提案、共用规则和内容校验准入，不要求用户逐主题手写，也不任意做笛卡尔组合。结构合法与语义质量分开记录；未核验字段不发布。Mission 的目标仍受真实授权资源限制，不能由主题生成器捏造。

Skill 至少定义：id／version、目标行为、适用情境、必需先修及可替代先修、推荐 readiness 线索、已有基础能力的自然应用方式、支架选项、观察 feature refs、assessment capability 与来源。先修应由内容审核确定；不能把旧“喜好表达是所有运动句子的先修”泛化到高阶能力。

GoalInstance 至多一个主要 skill，参数包括场景、表达任务范围、主要支架及观察方向。skill 来自允许的能力资源；主题情境、示例、素材和可选词卡可由 LLM 生成，只有通过所需准入的字段进入教学。生成器不能创建正式 KP、先修或学习事实；生成资源保留 llm_generated 来源。对普通交流允许自然生成的情境，不把它登记成已学知识。

TopicPack 的提前生成、内容检查、发布、存储、缓存与失效见 [tasking 第 2 节](topic-planner-tasking.md#2-topicpack-的拟议契约)和[独立主题服务](topic-management-service-design.md)。准入不是逐包人工审批；在线缓存 miss 不触发生成。自动流程依赖共用规则与抽样校准，不能仅凭有效 JSON 宣称语言／主题语义正确。

教学可用与评估可用分开。资源允许的高阶能力可以被选作实践方向，即使 semantic／independence assessment 尚未校准；此时 assessment capability 为 unassessed，总结只说明目标安排与有来源的实际活动，不能把未评估表达计为正式 attempted／独立／达成。

配套 [案例 catalog](eval-datasets/initial-planner-adaptation-v1/catalog.json)是供设计评审的有限合成资源，包含八类候选。它尚未经过教研能力审核，不得直接装载到生产或冒充官方 HSK 大纲。新增目标不以“覆盖四个人”作为审核依据。

## 4. 初始化教学决策

以下是一次有界 planConversation 的逻辑步骤，不要求拆成多个模型调用。

1. 宿主核对授权、三类一致快照和入口资源；提取明确选择，保留未知与截断。
2. 在当前主题／Mission 范围内形成少量候选，检查资源关联、硬先修与拒绝。先得到允许集合，不向模型提供“最佳答案”。
3. 模型确定交流目的，并提取相关 NeedAssessment。动机和交流风格可影响活动形式，兴趣只作为内容线索；学习需要由能力和记录支持。
4. 比较候选对本次目的的价值、需求证据、挑战范围、已练重复、支架负担与自然交流机会。选一个目标，或给出有依据的无目标决定。
5. 为首个机会安排有限内容、支持与待观察 feature，保留学生改选／拒绝的空间；不用固定答案或固定轮次路径。
6. Validator 核对提案并由宿主绑定版本。准备计划／首轮提示／页面来自同一已接受结果；更正、取消、资源更新或换学习者让旧准备失效。

### 4.1 允许与适合分别判断

**允许检查**是确定性边界：资源真实且同版本、目标引用存在、硬先修有来源、拒绝／权限／入口相容、支架与偏好无冲突。这些条件不能交给模型自行豁免。

**适合判断**比较当前价值：与交流目的及近期需要的关系、基线是否足以承受任务、已熟练内容是否有新的使用价值、能否自然获得表达机会。采用有依据的相对比较，不引入未经校准的数值评分或 HSK 阈值。

比较顺序：学生当前意愿与模式约束 → 目的相关的有证据需要 → readiness 与支架可承受性 → 重复／迁移价值 → 内容兴趣与活动便利。相近候选允许多解；不要求模型把这些因素排成生产代码固定权重。

已有可靠熟练证据的目标，不能仅因排在第一位被选作完整重教。当前主动复习、具体遗忘／困难或新的应用需求可以支持再次选择；使用熟练表达自然交流不等于重教。review_candidates 与等级都不能单独强制选择。

Validator 可拒绝明显的结构／来源冲突与无依据的“第一目标兜底”，但不能仅凭有效 refs 证明教学理由成立。剩余语义适合性通过独立案例和人工校准评估；不新增一个未校准 Judge 来“认证”所有在线计划。

### 4.2 无主要教学目标是有效决定

| planning_intent | 适用情况 | primary_goal | 首个行为 |
| --- | --- | --- | --- |
| targeted_practice | 有合适、允许且符合意愿的目标 | 一个 GoalInstance | 在交流中给一次相关表达机会 |
| supportive_conversation | 学生只想聊；当前基础够用；资源没有匹配需要 | null | 接住内容，按能力／偏好支持 |
| observe_then_decide | 资料不足／冲突，尚不能有依据选目标 | null | 一个自然、低压力的交流入口，收集必要线索 |

null 必须有受约束原因与来源，例如 student_prefers_conversation、no_suitable_goal、resource_gap、insufficient_evidence、current_purpose_supported、all_candidates_declined。普通自然交流是 conversation_purpose，不能借该字段隐藏一个强制练习任务。

有效但有限的资源没有合适目标可以 resource_gap；网络失败、签名失败或未知资源版本仍是准备失败。资料缺失不自动采用 HSK1 目标，也不连问水平测试。没有新输入时不靠定时器自动观察／升级。

## 5. 三个入口的差异

| 入口 | 初始重点 | 主要目标范围 | 无目标条件 |
| --- | --- | --- | --- |
| topic | 在选定主题里形成学生愿意的交流目的与适量挑战 | TopicPack 明确关联的 Skill catalog | 没有适合目标、只想交流、证据不足、拒绝等 |
| mission | 承接全部获授权 Mission 目标中的应用／补缺／迁移需要 | Mission 声明的目标与迁移范围 | 没有当前需要／合适目标或学生拒绝；不重做全套 Mission |
| free | 跟随当前选题，适配交流和语言帮助 | **初始 primary_goal=null、候选空** | 初始即合法无教学目标；持续练习请求在后续输入中按原规则修订 |

入口改变教学目的和目标范围，不能改变已有能力事实。学生明确拒绝教学时，topic／mission 也只交流；全部资源目标合法不构成强制教学理由。

## 6. 拟议输出契约与字段归属

建议新提案版本 initial-teaching-draft-v1 与新 conversation-plan 版本配套迁移，**不复用当前 conversation-plan-v1 字段却改变含义**。最终 schema 在实施前按以下职责冻结。

| 字段组 | 模型填写 | 宿主绑定／校验 |
| --- | --- | --- |
| 交流 | conversation_purpose、content_focus、至多两个可选开场 | 入口、主题／Mission 范围、可朗读且不泄漏内部 ID |
| 判断 | NeedAssessment 至多两项，最小理由与已有引用 | 引用路径／归属，来源覆盖与未知，不允许能力写入 |
| 选择 | planning_intent、primary_skill_id 或 null、实例参数、候选至多两个、no_goal_reason | skill／topic／Mission 关联、先修、拒绝；goal id、KP 与版本由宿主编译 |
| 支持 | 支架建议、任务深度、反馈重点、为何现在适合 | 当前语言／语速／纠错偏好、允许支持类型与回复预算 |
| 观察 | resource feature refs、待观察方向、未知项 | 仅 allowed feature，固定 required_student_answer:null；不能填观察结果 |
| 后续 | review trigger refs／允许动作，最多三项 | 仅资源／policy 支持的触发项；不直接执行或升级目标 |
| 权威元数据 | 不填 | identity、epoch、snapshot／resource versions、deadline、plan hash、path 与 planner_kind |

所有输出有界，至多一个主目标、一个首轮主要问题／任务、两个候选、两个 needs 与三个 triggers。目标说明不能列一串“描述＋比较＋论证＋反驳”。自由文本不成为新系统规则，内部简短判断不对学生播报。旧当前 API 需要明确版本适配与同源页面更新，不能让新页面读旧固定目标字段。

模型只输出完成决策所需的短字段。将派生的允许集合、有效 refs、coverage 与 required strategy 提供给模型；不输出思维链，不把姓名、测试 case id、expected goals 或未来对话放进 prompt。

初始化暂保持 10 秒总预算；主题方案将只读已发布包。现有逐轮总预算已改为 2 秒，从宿主接受有效 final 开始，包含等待、状态准备、LLM／body、修复、校验、降级和提交，跨层不能重置；正常预算预留 200ms 提交，剩余不足不发起模型／修复。运行拒绝超过 2 秒的配置与过期提案，并记录耗时。真实模型在此预算内的完成率及首音仍待实测，配置值不能证明体验合格。

## 7. 从计划到教学行动

同一个 Kai 的身份和安全规则保持稳定；能力适配通过 delivery_profile 表达任务深度、推荐支架、纠错重点与交流风格。后续 Context Compiler 必须把这些经过校验的字段编译给语音执行侧，避免新计划继续被固定 HSK1 人设覆盖。

| 维度 | 适配例子 | 约束 |
| --- | --- | --- |
| 任务深度 | 说一个喜好／讲清顺序／给具体例子／限定一句观点 | 依据证据与意愿，不按等级直接分配 |
| 支架 | 一个选择／局部词语／短示范／先让学生表达 | 支架是建议；未知的提示程度不变成事实 |
| 教师表达 | 初学者用具体短问，高阶用准确且简短的讨论入口 | 高阶不等于老师更长；沿用共享预算，必要调整另行验收 |
| 反馈 | 一个影响交流的点，或先回应内容不纠错 | 不制造错误，尊重纠错偏好 |
| 页面 | 目标、可选 Start Tip／词卡、诚实的无目标提示 | 与语音引用同一计划，不显示后台推理标签 |

这些是待实施的执行职责。初始计划在创建豆包会话前装配，可单独验证首轮遵循；后续 next_turn_advisory 仍只影响后续输入，不能由本设计推断当轮生成门控。

## 8. 反馈、重新判断与进步

初始化目标是可修订假设。首轮和后续输入使用真实此前执行与学生表现，不用预计答案、planned 支架或题目难度代替观察。

### 8.1 会中逐轮的处理链路

1. TeachingSession 接受唯一有效的完整输入，记录宿主时间；PlanningState 绑定 source_event_id／input revision、授权 epoch 和 2 秒 deadline。后续启动规划的等待不能重新获得预算。
2. 拒绝、换题、结束、打断和明确练习选择按控制规则先处理；归并当时目标、实际此前输出、提示／播放未知与当前输入的有来源反馈。原目标的观察不移给新目标。
3. 构造 immutable TurnPlan 输入：当前计划／目标、policy、语言、learner_feedback、actual_context、prior_execution、三类资料、资源与 goal_review。普通交流允许与目标无关，不要求每轮换目标。
4. Planner 选择一个下一步动作、支架、待观察方向及允许的目标修订；模型请求与最多一次修复共用剩余 deadline。过期输入不发请求，时间不足／超时明确走保守规则，不增加同步 Judge／主题生成调用。
5. Validator 检查引用、资源、先修、控制权与归属；校验／hash 后再次检查期限。只有仍有效的提案提交，迟到／取消结果不能覆盖新输入。规划事实、教学安排和学习证据分别保存。
6. 当前 next_turn_advisory 在安全回复边界更新后续输入建议，并记录实际生成／转发和未知播放；不能声称本轮自动语音严格等待计划。后续学生输入再次进入此链路。

当前代码已具有该链路的有限喜好／时间目标路径与 2 秒预算。TP-07 将它扩展到新 GoalInstance 和多主题能力；通用语义、基于表现自动提高挑战和正式本轮门控仍单独验收。

### 8.2 反馈与目标修订边界

| 观察／输入 | 可提出的调整 | 不能发生 |
| --- | --- | --- |
| 学生明确换题／拒绝／结束 | 即时暂停或清空，服从控制 | 换另一目标继续考试 |
| 学生当前主动求助 | 本轮最小支架；必要时重新评估任务 | 一次求助变成长期能力低标签 |
| 来源明确的表达尝试 | 减少重复完整示范、继续交流 | attempted 自动成为 independent／掌握 |
| 反复有来源的困难且仍愿练 | 降低问题负担，按合法资源考虑更小任务 | 用英文／沉默／关键词代替困难证据 |
| 经校准语义、提示与情境证据支持更大挑战 | 提出有限的新机会或目标修订，仍可拒绝 | 按轮数、两个命中或“我会了”自动升级 |
| 已选择无目标交流 | 尊重当前内容；有新输入／意愿才重新判断 | 在后台偷偷激活教学目标 |

初始版实施仍保留现有 goal lifecycle：目标替换／恢复受明确选择与现有困难规则约束；表中依据校准证据提高挑战属于后续独立实施项，必须另行更新 checkGoalPatch 与评测，不能仅改 prompt 越过当前约束。

ExpectedObservation 只定义希望看什么，例如“听者能否理解事件先后”“是否给出具体例子”；能力记录需未来已校准的观察机制。未支持的技能一直 unassessed。旧喜好／时间 attempted-only 写回、原目标归属、取消／更正隔离继续保留。

跨会话改进先使用用户获准保存的有来源记录，保留未知与期限；本设计不新增自动能力写入、生产持久化、自动修改提示词或在线训练。Agent 的系统质量改进通过版本化评测和人工复核完成。

## 9. 降级与异常

LLM 未配置／超时／非法输出必须单独记 rule／degraded_reason，不计 LLM 质量通过。规则可以依据匹配的结构化复习／未独立证据选择一个已经校验的保守目标；不得仅凭未掌握／未知就强制练习，也不得回选已熟练的第一个目标。

规则无法理解复杂历史或资源不匹配时，优先明确 supportive_conversation／observe_then_decide，保留原语言与当前控制。不能假装完成高阶 needs 判断或生成一个库外目标。规则路径与 LLM 路径都执行相同的授权、先修、拒绝、引用和取消检查。

读取失败、混版、撤权、取消与准备过期不会进入成功分母。模型忽略 abort 的迟到输出也不能覆盖新学习者或新资料。修复只处理有限格式／契约问题；剩余预算不足就明确降级，不无限反思。

## 10. 四个设计示例与多解

下表基于四位作者合成学习者的需要，统一篮球作为主题内情境以隔离兴趣差异；姓名只用于说明。例子是可接受方向，不是必须出现的目标 ID／句子，也不声称已产生真实计划。

| 背景需要 | 一个合理目标 | 其他可能合理的选择 | 应避免 |
| --- | --- | --- | --- |
| Alex：喜好表达需要示范，希望和朋友简单交流 | 自然表达喜好，逐步减少完整示范 | 有意愿且先修允许的简单运动安排；资料不确定时先交流观察 | 直接安排论证；因为 HSK1 固定跟读 |
| Maya：时间／频率已有证据，经历顺序需局部提示 | 讲一次运动经历，让听者理解先后 | 有近期依据的原因说明或计划叙述 | 完整重教喜好／时间；必须说“先…再…” |
| Leo：观点明确，理由笼统，希望聊团队配合 | 用具体例子展开一个理由 | 比较两种选择并解释权衡 | 套用 HSK5 模板；必须支持某个立场 |
| Nina：表达过于绝对，希望保留观点并加限定 | 限定一句观点的适用范围 | 调整措辞／语气；有来源的反驳任务 | 必须反驳 Kai；高级就多教多问 |

案例审阅评价目标、支持与证据之间的关系。无目标方案只有在对应来源／不确定性成立时合理，不能用 null 逃避所有明确需要。目标名称不同但行为相当可以通过；目标 ID 正确而理由／负担不合适可以失败。

## 11. 独立案例与防止固定映射

配套 [initial-planner-adaptation-v1](eval-datasets/initial-planner-adaptation-v1/README.md)包含四个基础例子与二十四个对照／边界，共 28 项设计案例。输入、拟议 catalog 和 oracle 分文件保存；仅输入与允许资源可进入未来 Planner。它们尚未接入 eval runner，没有新模型／语音结果或通过率。

主要对照包括：只改兴趣目标可以保持；只改当前需要应有合理响应；同等级不同需要；等级标签／姓名／UID／数组顺序变化不改变语义依据；同主题同兴趣但不同能力；完整熟练、缺失／截断／冲突、缺资源、拒绝与恢复、入口变化、Mission 多目标、来源／指令注入。所有输入是合成，不能把真实 learner-data 或运行回执当作预期答案。

### 11.1 三种断言

1. **确定性不变量**：授权、资源和先修、free 空目标、当前控制优先、来源／版本、固定答案为空、计划不写能力事实。检查错引用、越界和非法候选。
2. **语义可接受范围**：交流目的、需要、难度、支架、重复价值与自然表达机会。由校准后的人工／独立审阅评价，允许多解；合法 refs 不等于理由成立。
3. **metamorphic relations**：相同能力与需要、只换兴趣，内容可变而目标行为／难度应大体保持；只换需求／近期选择应合理改变优先级；只换名字、等级标签或列表顺序，允许候选重排但不能制造新的能力证据。

某个 oracle 的候选方向是例举范围，不是穷尽答案。评审前冻结断言；出现范围外合理计划，保留输出，由盲审按相同证据判断，登记 rubric 修订并重评全部相关候选，不能只为新版本补宽答案。确定性不变量无此豁免。

### 11.2 防止评测泄漏与记住案例

未来 harness 仅物化 inputs.json 与 catalog.json，不导入 oracles.json 的内容到生产或模型输入。case id、fixture key、姓名展示标签、预期目标、参考措辞、oracle、未来话轮都不传入 Planner；宿主生成匿名身份／来源引用并保存映射给评测器。原资源 ID 是课程来源，不能与测试 ID 混用。

prompt 不包含 Alex／Maya／Leo／Nina 示例或逐个等级到目标的映射。设计开发案例公开，另外准备未用于调 prompt 的 holdout 学习背景／主题变体；holdout 在模型选择前冻结。物化与裁剪后记录实际输入 hash，不仅记录 fixture hash；有界压缩不能悄悄丢掉导致正确选择的记录。

## 12. 评测与验收设计

保持旧十维评分、旧数据集与历史结果。新增初始化 rubric 独立版本，维度为 purpose_fit、need_grounding、goal_suitability、readiness_and_uncertainty、support_fit、learner_control、natural_opportunity、counterfactual_consistency。结果使用 pass／fail／review／unassessable，附有效来源；不把 unknown 补为通过。

| 层次 | 需要的证据 | 报告限制 |
| --- | --- | --- |
| 资料／契约 | 独立输入物化与来源／权限／版本不变量 | 不是教学质量分 |
| 初始计划 | 原始完整 pre-accept 输入与实际提案、拒绝／降级、语义审阅 | LLM／rule／失败分母分开；schema 成功不等于适配成功 |
| 对照一致性 | 成对输入差异、有效提案、独立比较 | 不要求字符串相同或四人目标全不同 |
| 首轮执行 | 同源 page/context hash、真实首轮输出与支持方式 | 合成设备与真实豆包分别报告；计划好不证明实际遵循 |
| 学习观察 | 实际学生表达、提示范围、语义与上下文 | 未校准能力保持 unassessed，不因目标选中提高证据状态 |

当前 onAcceptedProposal 只捕获逐轮；实施需新增初始化原始输入捕获，在目标实例编译／提案提交前绑定实际输入、允许集合和宿主策略。普通 Web 默认不保存完整画像／逐字稿，合成评测 artifact 才存 ignored .local；不得从接受后计划重建。

报告冻结模型／provider／prompt／提案／plan／catalog／policy／数据／rubric 版本、覆盖、实际延迟与取消及成本未知项。四个例子、24 个对照与 holdout 分组报告；合法模型返回、语义质量、降级率、等待可靠性分开。不同模型使用相同物化输入／资源／预算，多次运行分别保留全分母；重复次数与样本量在运行前登记，不从少量样本宣称统计改进。

实施验收至少满足：所有确定性硬门槛通过；四例及各类对照有可追溯语义复核且关键控制／来源／强制重教问题无未解决失败；缺口仍保持 review／unassessable；规则不冒充模型；旧跨入口回归无新增控制或证据问题。语义门槛与 holdout 应在运行前经人工校准冻结，当前不编造数值质量目标。真实首轮遵循、设备和正式当轮控制单独放行。
